# SafeZoo 대시보드 (`zoo_vision_jev_new.py`)

YOLO로 동물·사람을 찾고, 구역 규칙으로 경고한 뒤, 판단용 JSON을 만든다. AI에는 영상을 보내지 않는다. 탐지 결과, 구역 관계, 관측 시간, 사람 동석 여부만 보낸다. AI 응답은 기본 경고를 끄거나 설비를 제어하지 않는다.

실행은 프로젝트 가상환경으로 한다.

```powershell
& c:\code\code_test\zoo\.venv\Scripts\python.exe c:\code\code_test\zoo\zoo_safe\zoo_vision_jev_new.py
```

## 실행 방식

- 기본 실행: 판단용 JSON만 저장하고 API는 호출하지 않는다.
- `--jev`: TypeSafe API에 사건 요약 JSON을 보낸다. `TYPESAFE_API_KEY`가 필요하다.
- `--ollama`: 이 PC의 Ollama `/v1/systemone`에 판단을 요청한다.

`--jev`와 `--ollama`는 함께 쓸 수 없다.

## 경고 규칙

동물과 사람을 따로 본다.

- 동물: 발이 안전구역 밖이면 위험이다. 기린 카메라만 화면 하단도 위험이다.
- 사람: `person_inside`가 켜져 있고 발이 구역 안일 때만 위험이다. 구역 밖이나 화면 하단만으로는 경고하지 않는다.
- 후보 한 장, 특히 낮은 신뢰도 한 장은 사건을 만들지 않는다. 안전 쪽에서 이미 확인된 동물이 경계를 분명히 넘으면 그 전환은 바로 경고한다. 처음부터 밖에서만 보인 후보는 확인 시간이 지난 뒤에만 경고한다.
- 경계 완충 폭 안의 흔들림은 경고를 만들거나 끝내지 않는다. 안전 복귀가 확인된 뒤 다시 나가면 새 사건이다.
- 반복해서 높은 점수로 잡히는 나무 오탐은 시간 확인만으로 없어지지 않을 수 있다. 그 경우는 운영자가 검토한 탐지 제외 구역으로만 빼며, 나무 좌표를 코드에 넣지 않는다.

심각도는 항상 같게 두지 않는다. 사건 종류, 탐지 신뢰도, 위험 지속 시간에 따라 `경고`, `주의`, `참고`로 나눈다. 위 숫자는 시연용이며 현장 검증값이 아니다.

## 화면

왼쪽 메뉴는 홈, 카메라, 알림, 이벤트 로그, 스냅샷, AI 보조 판단, 설정이다. 기본 테마는 다크이고, 설정에서 밝게로 바꾸면 그 브라우저에 남는다. 메뉴 접기로 좁은 화면에서 사이드바를 숨긴다.

- 홈: 영상 연결, 분석 정상, 진행 경고, 미확인 알림. 미확인이 없으면 `미확인 알림 없음`이다. 영상 오류가 있으면 전체를 안전으로 적지 않는다.
- 카메라: 4분할과 1분할, ROI 표시와 감시 활성은 따로다. 구역 편집은 불러오기 전까지 자동으로 바뀌지 않는다. 안전구역과 탐지 제외 구역은 색과 저장 필드가 다르다.
- 알림: 사건 ID로 확인하고, 상세를 열기만 해서는 확인되지 않는다. 확인은 진행 중 상태를 끄지 않는다. 표시명은 미인증이다.
- 로그: 날짜, 카메라, 심각도, 종류, 확인 상태로 찾는다. 필터 초기화는 검색만 되돌린다.
- 스냅샷: 큰 미리보기는 높이 600px에서 시작한다. 파일이 없으면 `증거 이미지 없음`과 사건 정보를 보여 준다.
- AI: JSON 준비 모드, TypeSafe JEV, Ollama TEV를 서로 다른 이름으로 보여 준다. 고른 사건의 답만 그 사건에 붙인다.

## 보관과 복원

로그 목록 비우기와 스냅샷 목록 비우기는 삭제가 아니다.

- 대상은 종료됐고 운영자가 확인한 사건뿐이다. 미리보기에 나온 ID만 다시 검사해 보관한다.
- 로그 보관은 사진, ROI, AI 기록, 확인 상태를 바꾸지 않는다.
- 스냅샷 보관은 갤러리 기본 목록에서만 빠진다. 파일은 남고, 사건 상세에서는 보관 표시와 함께 볼 수 있다.
- 복원은 그 보관 표시만 되돌린다. 진행 중·미확인 사건과, 미리보기 뒤에 생긴 사건은 들어가지 않는다.

## 탐지 기준

설정 화면의 후보 점수, 확정 점수, 최소 관측 수, 확인 시간, 허용 누락 시간, 완충 폭, 안전 복귀 시간은 카메라와 클래스별로 저장된다. 한 카메라를 저장해도 다른 카메라에는 적용되지 않는다. 완충 폭의 단위는 프레임 짧은 변 길이의 비율이다. 변경 전후 값은 DB에 남는다.

기본 실행은 외부 AI를 호출하지 않는다. `--jev`와 `--ollama`를 켰을 때만 그 제공자를 부른다. AI가 꺼지거나 늦거나 틀린 답을 해도 규칙 경고는 남는다.

## 화면의 박스

박스는 분석한 그 프레임 위에만 그린다. 그래서 느린 분석의 옛 좌표가 최신 영상 위에 겹치지 않는다.

- 분석 시각이 1초를 넘고 `max_gap`(기본 3초) 안이면 `이전 분석 결과`라고 표시한다.
- `max_gap`보다 오래되면 박스를 숨기고, 최신 영상에 `분석 결과 만료 — 박스 숨김`을 표시한다.

## AI 요청

영상 읽기, YOLO 분석, AI 요청은 서로 다른 스레드다. 응답을 기다리는 동안 영상 분석은 멈추지 않는다.

같은 상황의 마지막 요청과 마지막 성공을 구분한다. API 오류, 휴지, 만료로 실패한 요청은 그 상황이 유지되는 동안 최대 3번만 다시 보낸다. 사람 동석 여부, 신뢰도 구간, 클래스가 바뀌면 횟수를 다시 센다.

완료된 답은 지우지 않는다. 사건이 아직 진행 중이고 `jev_ttl` 안인 `completed`만 화면에서 `현재 참고`다. 나머지는 `당시 기록`이다.

## 분석 스레드

시작 시 모델 로드가 실패하면 분석 스레드는 멈추고, 카메라 상태에 `분석 시작 실패`가 나온다. 동작 중이면 마지막 분석 성공 시각을 함께 보여 준다.


2026-10-07 실행에서 이 테스트 12개가 통과했다. 임시 DB만 쓴다. 운영 DB와 실제 영상으로 오경보·누락·지연을 재지는 않았다. 그래서 오탐이 줄었다고 말하지 않는다.

같은 날, 사용하지 않는 포트와 임시 데이터 폴더로 화면을 열었다. 1440×900에서 왼쪽 메뉴, 네 대 영상 연결, 분석 정상, `미확인 알림 없음`, JSON 준비 모드를 확인했다. 카메라 4분할, 알림 확인 버튼, 로그 보관 버튼, 스냅샷 빈 목록, AI 화면의 `최근 요청 없음`도 열렸다. 밝게 테마는 그 브라우저에 저장됐고 배경이 밝은색으로 바뀌었다. 화면을 옮기는 동안 분석 FPS는 계속 갱신됐다. 두 브라우저를 동시에 열어 확인 상태가 오가는지는 보지 못했다. 그 저장 자체는 임시 DB 테스트로 확인했다.

실제 영상 평가: 미실시. 합성 관측으로 낮은 점수 한 장, 확인된 동물의 이탈, 처음부터 밖인 후보, 경계 흔들림 뒤 재경고를 확인했다.
