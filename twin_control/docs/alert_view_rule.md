# 경보 큰 화면 (v13 후보 R13, v20 R20, v21 후보 R21)

2026-10-19 · 대상: 관제 화면 전체 (어느 탭에 있든 뜬다)

## 어떤 경보가 뜨나 (I1)

| 항목 | 규칙 |
| --- | --- |
| 대상 | 실제 영상 분석 사건만. 모의 재생기 사건은 띄우지 않는다 |
| 동물 이탈 | 기린 카메라(ZOO_CAM_GIRAFFE_01)의 동물 사건. `twin_server.py`의 `ALERT_EXIT_CAMERAS`로 카메라를 더할 수 있다 |
| 사람 침입 | 모든 카메라의 사람 사건 |
| 켜지는 조건 | 진행 중이고, 아직 "확인"하지 않았고, "오탐"으로 판정하지 않음 |
| 꺼지는 조건 | 사건 종료, "확인", "오탐". 경보가 하나도 남지 않으면 큰 화면이 저절로 닫힌다 |
| 묶기 | 같은 카메라·같은 종류의 사건은 한 칸으로 묶고 건수를 표시한다 |
| 순서 | 동물 이탈 → 사람 침입, 같은 종류는 먼저 시작한 순 |

서버는 `/api/state`의 `alerts`로 목록을 보낸다(I2). 항목마다 카메라, 종류, 동물, 대상 이름, 시작 시각, 건수, 사건 ID가 들어 있다. 사건 기록을 읽기만 하고 판정 코드는 바꾸지 않았다.

## 모양 (I3, I4)

- 화면 전체를 덮는 어두운 바탕 위에 경보 칸을 띄운다.
- 각 칸 위쪽 띠에 큰 글자로 "▲ 기린 관람 구역 · 구역 이탈 관측"을 쓰고, 그 옆에 카메라, 건수, 시작 시각을 둔다.
- 동물 이탈은 빨강 테두리와 띠, 사람 침입은 주황 테두리와 띠다.
- 띠 아래에 그 카메라의 실시간 영상을 크게 보여 준다(박스와 구역선 포함).
- 칸마다 "확인" 버튼이 있다. 누르면 그 칸에 묶인 사건을 모두 확인 처리한다.
- 위쪽 "닫기"는 화면만 닫는다. 경보는 계속 진행되고, 상단 바의 "경보 큰 화면 (N)"으로 다시 열 수 있다. Esc로도 닫힌다.

## 분할 (I5)

| --- | --- |
| 1건 | 화면 전체 |
| 2건 | 좌우 반씩 |
| 3~4건 | 2×2 |
| 5건 이상 | 앞의 4건을 2×2로, 나머지는 아래에 목록으로 |

## 반복 팝업 억제 (I6)

- 새 사건이 생기면 큰 화면이 자동으로 열린다.
- 사용자가 닫은 경보(같은 카메라·같은 종류)는 60초 동안 새 사건이 붙어도 자동으로 다시 열지 않는다. 다른 카메라나 다른 종류의 경보는 바로 연다.
- 칸 구성이 바뀔 때만 영상을 다시 연결한다. 건수와 시각 글자만 바뀌면 영상은 끊지 않는다.

## 영상 연결 수

- 브라우저는 한 서버에 연결을 6개까지만 연다.
- 큰 화면이 열려 있는 동안에는 통합 관제·카메라 탭의 작은 영상 칸이 스트림을 쉬고 "경보 큰 화면에서 보는 중"을 보여 준다.
- 큰 화면을 닫으면 작은 영상이 다시 이어진다.

## 확인 (I9, 시험 서버)

| 시험 | 결과 |
| --- | --- |
| 단일 경보 | 레서판다 사람 침입 → 주황 큰 화면 자동 열림, 작은 영상 스트림 0개, 큰 화면 스트림 1개 |
| 종류 바뀜 | 레서판다 경보가 끝나고 기린 이탈이 생기자 빨강 큰 화면으로 바뀜 |
| 동시 경보 | 기린 이탈 + 레서판다 침입 → 좌우 분할 (빨강/주황) |
| 닫기 | 큰 화면 닫힘, 작은 영상 4개 다시 연결, "경보 큰 화면 (1)" 버튼 표시 |
| 확인 버튼 | 기린 경보의 사건이 확인 처리되어 목록에서 빠짐 |
| 반복 억제 | 레서판다 경보를 닫은 뒤 45초 동안 새 레서판다 사건 13건이 열렸지만 자동으로 다시 열리지 않음 |
| 판정 동일성 | `twin_replay.py` 네 카메라 출력이 이전과 같음 |

3~4건(2×2)과 5건 이상(목록)은 시험 영상에서 동시에 생기지 않아 화면으로 보지 못했다. 코드로만 확인했다.

## 알아 둘 점

- 시험 영상은 반복 재생되므로 레서판다 카메라에서 사람 침입이 자주 생긴다(45초에 13건). 실제 현장에서는 60초 억제가 팝업 남발을 줄인다.
- 경보 설정 파일(I8)과 2단계 일정(I10), 부하 측정(I7)은 선택되지 않았다.

### 배치와 색 (I2, I5)

| 칸 수 | 배치 |
| --- | --- |
| 1개 | **왼쪽 카메라 영상 · 오른쪽 2D GIS 지도 (5:5)** |
| 2개 이상 | 이전과 같음 (영상만 좌우·2×2·목록). I7(다중 경보 2분할 규칙)은 고르지 않았다 |

| 경보 | 영상 띠·테두리 | 지도 칸 테두리 | 지도 안 |
| --- | --- | --- | --- |
| 실제 이탈 | 빨강 실선 | 빨강 실선 | 구역 빨강 테두리, 카메라 위 빨강 "!" (v19) |
| 실제 사람 침입 | 주황 실선 | 주황 실선 | 구역 주황 테두리, 카메라 위 주황 "!" (v19) |
| 코끼리 모의 이탈 징후 | 빨강 사선 띠, **점선** 테두리, "모의" 표시 | 빨강 **점선** | 모의 동물 위치·경보 "!"(점선 원) |

- 실선은 실제 분석, 점선은 모의다(v8 규칙).
- 모의 칸의 영상은 CAM-01의 실시간 영상이고, 띠 문구에 "영상은 실시간, 경보는 모의"라고 쓴다.
- 지도는 새로 그리지 않는다. 통합 관제의 2D 지도를 큰 화면 오른쪽으로 옮겨 오고, 같은 그리기 함수가 계속 갱신한다. 닫히거나 칸이 2개 이상이 되면 제자리로 돌려놓는다.
- 지도가 큰 화면에 있는 동안에는 지도 클릭 시작 팝오버를 띄우지 않는다.
- 지도 제목에 카메라, 구역, 색의 뜻을 쓴다(예: "CAM-02 기린 관람 구역 · 애니멀팜 구역 · 빨강 ! = 이탈").

### 서버 신호 (I3)

`/api/state`의 `alerts` 항목에 `zone`(지도 구역 id: forest·farm·safari…)을 더했다.
- 값은 `map/naturepark.json`의 `cameras[].live → zone`에서 읽는다.
- 기존 필드(camera, kind, animal, object_ko, since, count, event_ids)는 그대로다. 시작 시각은 기존 `since`다.
- 판정 코드는 바꾸지 않았다.

## R21 (v21 후보): 코끼리 모의 경보는 지도만, 첫 화면 카메라 4분할 복귀

### 지도 전용 큰 화면 (I4)

- **조건:** 큰 화면 칸이 코끼리 모의 경보 하나뿐이다.
- **배치:** 영상 칸을 숨기고 지도를 전체 폭으로 보여 준다.
- **스트림:** 큰 화면 안에서 여는 영상 스트림은 0개다.
- **지도 제목 줄:** 경보 띠 역할을 한다. 왼쪽에 "▲ 초식동물 숲 · 이탈 징후 (Level 3)"와 설명("점선·빨강 ! = 코끼리 이탈 징후 (모의, 영상 없음)"), 오른쪽에 "◇ 모의"와 "확인 (모의)" 버튼이 있다.
- **테두리:** 빨강 점선(모의)이다.
- **다른 경보와 함께일 때:** 칸이 2개 이상이면 이전처럼 칸을 나눈다. 코끼리 모의 칸에는 영상 대신 "모의 경보라 영상은 띄우지 않습니다"가 나온다.
- **실제 경보:** 기린 이탈, 사람 침입의 영상 | 지도 2분할(R20)은 그대로다.
