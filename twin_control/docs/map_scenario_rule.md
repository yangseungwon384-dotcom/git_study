# 실영상 시나리오와 2D 관제 지도 연동 (v19 후보, R18)

2026-10-19 · 대상: 통합 관제 탭의 재생기, GIS 트윈 맵(2D)

## 목표

모의 시나리오는 코끼리만 남기고, 실영상 시나리오(기린 이탈, 레서판다 사람 침입)를 2D 관제 지도와 연결한다. 판정 규칙과 코끼리·호랑이 분석은 바꾸지 않는다.

승인된 개선안 7개를 작업했다. 3D 지도 항목은 승인되지 않아 3D 지도는 바뀌지 않았다.

## 모의 시나리오 정리 (I2)

| 시나리오 | 결과 |
| --- | --- |
| 코끼리 이탈 징후 (Level 3) | 그대로 (모의, 점선 표시) |
| 관람객 제한 구역 접근 (Level 2) | 삭제 |
| 카메라 신호 지연 (Level 1) | 삭제 |

- 두 시나리오의 연결 파일 `scenario_map.json`은 `scenario_map.json.removed`로 보관했다. `/api/scenario-map`과 동물 카드의 보라 "◇ 모의" 배지도 없앴다.
- 첫 화면의 예시 사건 기록(CAM-04 신호 지연, 관람객 울타리 접근)은 시나리오가 아니라 화면을 처음 열 때 깔리는 모의 기록이라 그대로 두었다.

## 동작 명세 (I1)

### 시나리오 단계 (서버 기준, I3)

`/api/state`의 `cameras[].video`에 서버가 정한 단계를 보낸다. 지도는 이 값만 따르고 브라우저가 따로 추측하지 않는다.

| 필드 | 뜻 |
| --- | --- |
| `phase` | `playing` 위험 영상 재생 중 · `ended` 끝난 지 30초 이내 · `idle` 평소 영상 |
| `ended_by` | `done` 영상을 끝까지 재생 · `reset` 도중에 초기화 |
| `ended_ago` | 끝난 뒤 지난 초 |
| `sec`, `duration` | 지금 위치와 영상 길이 |

### 지도 모습 (I4, I5)

모두 실제 분석이라 실선으로 그린다(v8 규칙). 모의인 코끼리 시나리오와 모의 동물 위치는 이전처럼 점선이다.

| 상황 | 구역 테두리 | 카메라 | 글자 |
| --- | --- | --- | --- |
| 재생 중 | 파란 실선 (굵게) | 파란 실선 링 | "▶ 기린 이탈 (실영상) 재생 중 12/24초" |
| 실제 이탈 경보 | 빨강 실선 | 카메라 위 빨간 "!" (깜빡임) | "이탈 1건" |
| 실제 사람 침입 경보 | 주황 실선 | 카메라 위 주황 "!" (깜빡임) | "사람 침입 1건" |
| 끝남 (30초 동안) | 평소 | 평소 | "■ … 끝남" 또는 "■ … 초기화됨" |
| 평소 | 평소 | 평소 (실영상 파랑) | 없음 |

- **실제 경보의 기준:** 경보 큰 화면(v13)과 같은 서버 `alerts`다. 진행 중이고, 확인하지 않았고, 오탐이 아닌 기린 이탈과 사람 침입이다. 사건이 끝나거나 확인·오탐 처리되면 지도에서도 사라진다.
- **색의 우선순위:** 실제 경보 > 선택한 구역(흰색) > 재생 중(파랑). 선택해 둔 구역이어도 경보 색은 가려지지 않는다.
- **글자 위치:** 카메라 바깥쪽(지도 왼쪽 절반의 카메라는 왼쪽, 오른쪽 절반은 오른쪽)에 두고, 지도 맨 위 층에 그려 다른 표시에 가리지 않는다.
- 2D 지도에서는 기린(CAM-02)과 레서판다(CAM-05)가 같은 애니멀팜 구역에 임시 배치돼 있다. 두 카메라 중 하나라도 경보가 있으면 애니멀팜 테두리가 그 색이 된다(이탈이 침입보다 우선).

### 지도에서 시작하기 (I6)

1. 지도에서 카메라(CAM-02, CAM-05)나 구역(애니멀팜)을 누른다.
2. 그 자리의 실영상 시나리오 목록이 팝오버로 뜬다. 구역을 누르면 그 구역 카메라의 시나리오가 모두 나온다.
3. "▶ 시작"을 누르면 재생기와 같은 경로(`POST /api/scenario-video/{카메라}/start`)로 시작한다.

- 팝오버가 확인 단계 역할을 한다. 누르자마자 시작하지 않는다.
- 이미 재생 중이면 버튼 대신 "재생 중 12/24초"를 보여 주고 누를 수 없다(v17과 같이 다시 시작하지 않음).
- 실영상 시나리오가 없는 카메라·구역을 누르면 팝오버가 뜨지 않고, 이전처럼 선택만 된다.
- "닫기", Esc, 팝오버 바깥 클릭으로 닫힌다.

## 확인 (I7, 시험 서버)

| 시험 | 결과 |
| --- | --- |
| 재생기 목록 | 모의 "코끼리 이탈 징후 (Level 3)" 하나, 실영상 2개. `/api/scenario-map`은 404 |
| 코끼리 모의 시나리오 | 1/8, 2/8 단계가 이전처럼 진행 |
| 지도에서 기린 시작 (CAM-02 클릭 → 시작) | 파란 링·"재생 중 n/24초" → 21초쯤 빨간 "!"·"이탈 1건" → 끝나자 "■ 끝남" |
| 지도에서 레서판다 시작 (구역·카메라 클릭) | 구역을 누르면 두 시나리오가 함께 나옴. 12초쯤 주황 테두리·"!"·"사람 침입 1건" |
| 재생 중 초기화 | `phase` ended, `ended_by` reset, "■ 초기화됨" 표시, 30초 뒤 `idle`이 되며 글자 사라짐 |
| 그리기 시간 | 2D 지도 한 번 그리기 중앙값 0.4~0.5ms (예산 1ms 이하) |
| 판정 동일성 | `twin_replay.py` 네 카메라 출력이 v18과 같음 |
| 평소 영상 중 지도 경보 | 14:42~14:48 동안 5초마다 60번 확인, 경보 0건 (두 카메라 모두 idle) |

## 한계

- 3D 지도는 이번 범위가 아니어서 시나리오 진행과 경보 "!"가 2D에만 나온다. 3D의 실제 사건 붉은 기둥은 이전처럼 있다.
- 기린·레서판다 카메라 위치는 안내도에 없어 임시 배치다(애니멀팜). 실제 위치가 정해지면 지도 좌표만 고치면 된다.
- 지도에서 시작하는 권한은 재생기와 같다. 로그인한 모든 계정이 시작할 수 있다.

## R24 (v24 후보): 실영상이 아닌 곳은 지도에서 눌러도 반응하지 않음

2026-10-22 · 승인 항목: I1 클릭 대상 명세, I2 2D 지도 비활성 처리, I3 서버 시작 요청 제한, I8 회귀 시험

### 원인

지도에서 실영상이 아닌 곳을 누르면 그 자리의 모의 카메라가 선택됐다.
- 모의 카메라: CAM-03 메인광장, CAM-04 바람의 언덕, CAM-12 카약 탑승장
- 그 결과 첫 화면 카메라 4칸 중 마지막 칸(CAM-05)이 모의 카메라로 바뀌었다. 가짜 박스를 그린 모의 화면이 커져서 보였다(고객이 말한 "이상한 객체 영상").

### 클릭 규칙 (I1)

| 지도에서 누른 것 | 결과 |
| --- | --- |
| 실영상 카메라 CAM-01 코끼리, CAM-07 호랑이 | 이전과 같음: 선택, 첫 화면에서 그 카메라 확대 |
| 실영상 카메라 CAM-02 기린, CAM-05 레서판다 | 이전과 같음: 선택, 확대, 실영상 시나리오 시작 팝오버 |
| 실영상 카메라가 있는 구역 (초식동물 숲, 워킹 사파리, 애니멀팜) | 이전과 같음 |
| **모의 카메라 CAM-03·04·12** | **반응 없음** |
| **실영상 카메라가 없는 구역 (바람의 언덕, 메인광장, 카약 탑승장)** | **반응 없음** |
| 동물 표시 | 선택(상세 보기)은 그대로. 그 동물의 카메라가 모의 카메라(예: 수달 → CAM-12)이면 카메라 칸을 바꾸지도 키우지도 않음 |

목표 문장("실영상 아닌 곳")에 따라 코끼리·호랑이 실영상 카메라는 비활성으로 두지 않았다. 오피스 질문의 "코끼리·호랑이·건물까지 전부"는 답이 없어 적용하지 않았다. 대피 건물·출입문은 원래 눌러도 반응이 없다.

### 화면 처리 (I2)

- 지도 클릭에서 모의 카메라와 실영상 카메라 없는 구역은 바로 무시한다.
- 선택 함수(`select`)도 고쳤다. 실영상 분석 중에는 어떤 경로로든 모의 카메라를 카메라 칸에 넣거나 키우지 않는다. 동물 카드나 사건 목록에서 골라도 같다.
- 3D 지도(I7)는 고르지 않았다. 다만 3D에서 고른 결과도 같은 선택 함수를 거치므로 모의 카메라가 카메라 칸에 들어오지 않는다.

### 서버 (I3)

서버는 v17부터 `scenario_video.json`에 없는 카메라의 시작 요청(`POST /api/scenario-video/{카메라}/start`)을 404로 거절하고 있었다. 이번에 다시 확인만 하고 바꾸지 않았다.
