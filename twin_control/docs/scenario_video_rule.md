# 실영상 시나리오 (v17 후보, R16)

2026-10-19 · 대상: 기린(CAM-02)·레서판다(CAM-05) 카메라, 재생기

## 목표

기린·레서판다 카메라는 평소에는 평범한 영상을 반복 재생하고, 재생기에서 시나리오를 시작할 때만 위험 영상으로 바꾼다. 판정 규칙과 코끼리·호랑이 카메라는 바꾸지 않는다.

## 동작 명세 (I1)

| 상황 | 동작 |
| --- | --- |
| 서버 시작 | 두 카메라 모두 평소 영상을 반복 재생 |
| 시나리오 시작 | 재생기에서 "기린 이탈 (실영상)" 또는 "레서판다 사람 침입 (실영상)"을 고르고 "시나리오 시작". 그 카메라만 위험 영상 처음부터 재생 |
| 완료 | 위험 영상의 마지막 프레임까지 한 번 재생하면 평소 영상으로 돌아간다 (반복하지 않음) |
| 초기화 | 재생기 "초기화"를 누르면 모의 상태를 지우고, 시나리오 영상이 돌고 있는 카메라도 바로 평소 영상으로 돌린다 |
| 진행 중 다시 시작 | 무시한다. 처음부터 다시 틀지 않는다 (오피스 질문에 답이 없어 이렇게 정했다) |
| 다른 카메라 | 기린 시나리오 중에 레서판다 시나리오를 따로 시작할 수 있다. 둘은 서로 영향을 주지 않는다 |
| 모의 시나리오와 함께 | 실영상 시나리오는 서버 영상을, 모의 시나리오는 브라우저 화면만 바꾸므로 같이 돌아도 된다 |
| 누가 | 로그인한 계정이면 누구나 (관리자 제한은 고르지 않음). 영상 전환은 접속한 모든 화면에 같이 보인다 |

실영상 시나리오는 실제 분석을 거치므로 사건 기록, 경보 큰 화면, 판단 AI 요청이 모두 평소처럼 생긴다. 모의 시나리오는 이전처럼 DB 기록과 AI 요청이 0건이다.

## 설정 (I2)

`scenario_video.json`에서 카메라별로 평소 영상(`normal`), 위험 영상(`scenario`), 재생기 이름(`title`)을 정한다.

- 파일 이름은 영상 폴더 기준이다(`--source-dir`, 저장소를 통째로 받은 PC는 저장소 폴더, v16 규칙).
- 평소 영상 파일이 없으면 그 카메라는 이전처럼 위험 영상만 반복한다. 서버 창에 안내가 뜬다.
- 여기 없는 카메라(코끼리·호랑이)는 엔진의 원래 재생을 그대로 쓴다.
- 바꾸면 서버를 다시 시작해야 한다.

## 영상 전환과 사건 정리 (I3, I4)

- 엔진(`zoo_vision_jev_new.py`)은 고치지 않았다. `twin_vision.py`의 분석기가 두 카메라의 재생 스레드만 바꿔 끼운다. 영상을 읽는 방식(실시간 속도, 늦으면 건너뛰기, 화면 크기 맞추기)은 엔진과 같다.
- 영상이 바뀌는 순간 그 카메라의 추적, 진행 중 사건, 정지 물체 기록을 모두 비운다. 엔진이 영상 반복 때 하는 정리와 같다. 그래서 이전 영상의 사건이 새 영상으로 이어지지 않는다.
- 진행 중이던 사건은 종료 사유를 구분해 닫는다.
  - 시작·초기화로 바뀐 경우: "영상 전환"
  - 위험 영상이 끝나 돌아온 경우: "시나리오 영상 끝"
  - 평소 영상이 반복될 때: "영상 반복" (이전과 같음)
- 사건 DB의 기존 기록은 그대로 둔다.

## 서버 API (I3, I5)

| 요청 | 하는 일 |
| --- | --- |
| `GET /api/scenario-video` | 실영상 시나리오가 있는 카메라와 이름 |
| `POST /api/scenario-video/{카메라}/start` | 그 카메라를 위험 영상으로. 이미 재생 중이면 `started=false` |
| `POST /api/scenario-video/reset` | 위험 영상이 돌고 있는 카메라를 모두 평소 영상으로 |
| `/api/state`의 `cameras[].video` | `mode`(normal/scenario), `title`, `sec`(지금 위치), `duration`(영상 길이). 두 카메라에만 있고 나머지는 `null` |

## 화면 (I5, I7)

- 재생기 시나리오 목록을 "모의 (이 브라우저 안에서만)"와 "실영상 (서버 영상 전환 · 모든 화면 · 사건 기록됨)" 두 묶음으로 나눴다.
- 실영상 시나리오가 도는 동안 재생기 안내 줄에 "시나리오 영상 재생 중 (12/24초)"를 보여 준다. 끝나면 "평소 영상으로 돌아왔습니다"를 보여 준다.
- 카메라 칸(첫 화면, 카메라 탭) 왼쪽 아래에 배지를 단다.
  - 평소 영상: 회색 테두리 "평소 영상"
  - 시나리오 영상: 주황 채움 "▶ 시나리오 영상 12/24초"
  - 모의 표시(보라 점선)와 겹치지 않는다.
- 경보 큰 화면의 띠에도 "· 평소 영상" 또는 "· ▶ 시나리오 영상"을 붙인다.

## 확인 (I6, I10)

| 시험 | 결과 |
| --- | --- |
| 기린 시나리오 | 시작 → 위험 영상(24초)으로 전환, 21초쯤 이탈 경보와 큰 화면, 끝나자 평소 영상으로 자동 복귀. 진행 중 사건은 "시나리오 영상 끝"으로 닫힘 |
| 진행 중 다시 시작 | 무시됨. 영상 위치가 이어서 흘러감 (처음부터 다시 틀지 않음) |
| 레서판다 시나리오 + 초기화 | 11초쯤 사람 침입 경보, "초기화"를 누르자 바로 평소 영상으로 돌아오고 진행 중 사건은 "영상 전환"으로 닫힘 |
| 다른 카메라 | 전환 중에도 코끼리·호랑이 영상과 분석은 그대로 (분석 2.4~2.8 fps) |
| 판정 동일성 | `twin_replay.py` 네 카메라 출력이 이전(R5 기준)과 같음 |
| 평소 영상 사전 측정 (`twin_replay.py`, 영상 3회 반복) | 기린 0건. 레서판다는 영상 한 바퀴(20초)마다 사람 진입 2건 |
| 평소 영상 10분 (시험 서버) | 기린·코끼리·호랑이 0건. **레서판다 사람 침입 18건** |

## 한계: 레서판다 평소 영상 오탐 (v18에서 고침)

v17에서는 레서판다 평소 영상에서 사람 침입이 10분에 18건 생겼다.

- 원인: 레서판다 자신을 YOLO가 사람으로 봤다(신뢰도 0.65~0.80).
- v17 보고 때는 "나뭇가지"라고 적었다. 박스 좌표의 축척을 잘못 맞춰 다른 자리에 그린 탓이었다.
- R17에서 레서판다 카메라에만 사람 박스 모양 규칙을 넣어 고쳤다. 기준: `docs/redpanda_person_rule.md`.

## 고르지 않은 항목

- 배지 시안 검토(I8): 따로 시안을 만들지 않았다. I7에 필요한 만큼만 배지 색을 모의 보라와 다르게 정했다.
- 재생기 마크업 분리(I9): 따로 하지 않았다. I5에서 실영상 항목을 모의 항목과 헷갈리지 않게 목록 묶음 이름만 나눴다.
- 이식성 반영(I11): GitHub `ZOO-CONTROL(최종)` 브랜치에 평소 영상 2개와 설정 파일을 올리지 않았다. 지금 브랜치를 받은 PC에서는 평소 영상이 없어 이전처럼 위험 영상만 반복한다.
