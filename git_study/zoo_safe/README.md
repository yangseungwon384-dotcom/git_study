# SafeZoo 대시보드 (`zoo_vision_jev_new.py`)

YOLO로 동물·사람을 찾고, 구역 규칙으로 경고한 뒤, 판단용 JSON을 만든다. AI에는 영상을 보내지 않는다. 탐지 결과, 구역 관계, 관측 시간, 사람 동석 여부만 보낸다. AI 응답은 기본 경고를 끄거나 설비를 제어하지 않는다.

실행은 프로젝트 가상환경으로 한다.

```powershell
& c:\code\code_test\zoo\.venv\Scripts\python.exe c:\code\code_test\zoo\zoo_safe\zoo_vision_jev_new.py
```

## 실행 방식

- 기본 실행: 판단용 JSON만 저장하고 API는 호출하지 않는다.
- `--jev`: TypeSafe API에 사건 요약 JSON을 보낸다. `TYPESAFE_API_KEY`가 필요하다.
- `--ollama`: 이 PC의 Ollama `/v1/systemone`에 판단을 요청한다.

`--jev`와 `--ollama`는 함께 쓸 수 없다.

## 경고 규칙

동물과 사람을 따로 본다.

- 동물: 발이 안전구역 밖이면 위험이다. 기린 카메라만 화면 하단도 위험이다.
- 사람: `person_inside`가 켜져 있고 발이 구역 안일 때만 위험이다. 구역 밖이나 화면 하단만으로는 경고하지 않는다.
- 안전에서 위험으로 바뀌면 바로 배너와 사건을 만든다. 0.8초 이상 안전으로 돌아오면 같은 추적 ID도 다음 이탈에서 다시 즉시 경고한다.

심각도는 항상 같게 두지 않는다. 사건 종류, 탐지 신뢰도, 위험 지속 시간에 따라 `경고`, `주의`, `참고`로 나눈다.

## 화면의 박스

박스는 분석한 그 프레임 위에만 그린다. 그래서 느린 분석의 옛 좌표가 최신 영상 위에 겹치지 않는다.

- 분석 시각이 1초를 넘고 `max_gap`(기본 3초) 안이면 `이전 분석 결과`라고 표시한다.
- `max_gap`보다 오래되면 박스를 숨기고, 최신 영상에 `분석 결과 만료 — 박스 숨김`을 표시한다.

## AI 요청

영상 읽기, YOLO 분석, AI 요청은 서로 다른 스레드다. 응답을 기다리는 동안 영상 분석은 멈추지 않는다.

같은 상황의 마지막 요청과 마지막 성공을 구분한다. API 오류, 휴지, 만료로 실패한 요청은 그 상황이 유지되는 동안 최대 3번만 다시 보낸다. 사람 동석 여부, 신뢰도 구간, 클래스가 바뀌면 횟수를 다시 센다.

완료된 답은 지우지 않는다. 사건이 아직 진행 중이고 `jev_ttl` 안인 `completed`만 화면에서 `현재 참고`다. 나머지는 `당시 기록`이다.

## 분석 스레드

시작 시 모델 로드가 실패하면 분석 스레드는 멈추고, 카메라 상태에 `분석 시작 실패`가 나온다. 동작 중이면 마지막 분석 성공 시각을 함께 보여 준다.
